### 1. i-node (아이노드)의 핵심 개념

* **정의 및 역할:** 파일의 메타데이터(정보)와 실제 데이터가 저장된 물리적 위치(블록 주소)를 관리하는 핵심 자료구조이다.
* **필수 할당:** 파일 시스템 내에서 파일이 하나 생성될 때마다 무조건 1개의 고유한 i-node가 할당된다.
* **포함하는 정보:** 파일 크기, 소유자, 접근 권한(rwx), 타임스탬프(생성/수정 시간), 하드 링크 수, 데이터 블록을 가리키는 주소 포인터 등 파일에 대한 모든 상태 정보를 저장한다.

### 2. 데이터 블록 (Data Block)과의 관계

* **역할:** 파일의 실제 내용(텍스트, 바이너리 데이터 등)이 물리적으로 기록되는 공간이다.
* **동적 할당:** 파일 내부에 내용이 전혀 없는 빈 파일이라면, i-node만 존재하고 데이터 블록은 아예 할당되지 않을 수 있다.
* **분할 저장:** 저장해야 할 파일의 크기가 1개 데이터 블록의 기본 용량을 초과하면, 그 크기를 감당하기 위해 여러 개의 데이터 블록이 추가로 쪼개어 할당된다.

### 3. 데이터 블록 위치 지정 (포인터) 방식

파일 시스템은 파일의 크기가 커짐에 따라 접근 방식을 **직접 블록 → 간접 블록 → 이중 간접 블록** 순으로 단계적으로 확장하여 데이터를 관리한다.

* **직접 블록 (Direct Block):** i-node 내부에 실제 데이터 블록의 물리적 주소를 직접 저장한다. 작은 크기의 파일을 저장하는 데 쓰이며, 중간 탐색 과정이 없어 접근 속도가 가장 빠르다.
* **간접 블록 (Single Indirect Block):** i-node가 데이터 블록을 직접 가리키지 않고, '실제 데이터 블록 주소들의 목록'을 담고 있는 또 다른 인덱스 블록을 가리킨다. 비교적 큰 파일을 저장할 때 사용되며, 주소를 한 번 거쳐 가야 하므로 직접 블록보다 탐색 및 접근 속도가 느리다.
* **이중 간접 블록 (Double Indirect Block):** i-node가 1차 인덱스 블록을 가리키고, 그 블록이 다시 2차 인덱스 블록을 가리킨 후 최종 데이터 블록에 도달하는 구조다. 매우 큰 대용량 파일을 저장할 수 있게 해주지만, 주소 탐색을 두 번이나 거쳐야 하므로 접근 속도는 가장 느리다.
